# MoonCast · MoonBit 纯 P2P 直播协作

MoonCast 是参加 [2026 MoonBit 黑客松](https://moonbitlang.github.io/Hackathon2026/) 的作品。它把我此前开发的 [Syncast](https://github.com/KonnyakuMatcha/Syncast) 核心直播体验用 MoonBit 重新实现为一个可运行、可验证的浏览器应用：房主共享屏幕和来源声音，成员进行语音通话，媒体数据始终在浏览器之间直接传输。

项目目标不是简单演示 API，而是验证一条清晰的 MoonBit + WebRTC 路径：**用 MoonBit 管理客户端状态机、协商流程和拓扑决策，用浏览器原生能力完成媒体传输**。

## 项目亮点

- **MoonBit 承担客户端主逻辑**：房间状态、成员状态、双通道连接、offer/answer、trickle ICE、控制消息、恢复策略和浅层树拓扑都在 `cmd/main/main.mbt` 中编排。
- **语音 mesh**：所有成员之间建立独立语音 P2P 连接，支持静音和成员状态同步。
- **浅层树状画面转发**：少量观众由房主直连；观众较多时选择最多三个第一层中转，每个中转继续带子节点，降低房主上行压力。
- **画质档位**：观众可选择流畅 720p30、清晰 1080p30 或高帧 1080p60；发送端按接收端请求调整分辨率、码率和帧率。
- **连接恢复**：`failed` 立即恢复，`disconnected` 延迟观察；最多三轮重建，并支持手动重连。
- **纯 P2P 媒体链路**：信令服务器只转发 SDP/ICE，不接收、存储或转发画面与声音。
- **STUN 打洞，拒绝 TURN**：本地与远端 relay 候选都会被过滤；无法直连时宁可失败，也不悄悄回退到服务器中继。

## 当前功能

- 房间创建与 6 位房间码加入
- HTTP 长轮询事件流
- 成员加入、离开、静音和连接状态展示
- 成员间语音 mesh
- 房主屏幕视频与来源音频共享
- 浅层树状画面拓扑与动态重规划
- WebRTC offer/answer 协商
- Trickle ICE 候选交换与早到缓存
- ICE `failed` / `disconnected` 自动恢复
- 手动重新连接
- 观众画质选择与发送端参数调整
- 共享声音开关
- 房主停止共享、成员离开和房主关闭房间

## 技术架构

```text
                    ┌────────────────┐
                    │ MoonBit 状态机 │
                    └───────┬────────┘
                            │ JS FFI / callbacks
                    ┌───────┴────────┐
                    │ 浏览器 API 桥 │
                    └───────┬────────┘
              getUserMedia / getDisplayMedia / RTCPeerConnection
                            │
      ┌─────────── P2P voice mesh ───────────┐
      │                                     │
房主浏览器 ─── stage ── 第一层观众 ─── 叶子观众
      │                                     │
      └──────────── Python 信令服务器 ───────┘
```

### 代码结构

| 路径 | 说明 |
|---|---|
| `cmd/main/main.mbt` | MoonBit 客户端状态机与协商编排 |
| `lib/topology.mbt` | 浅层树拓扑规划 |
| `static/bridge.js` | DOM、fetch、媒体捕获、WebRTC 和音频播放适配 |
| `static/main.js` | MoonBit 编译产物 |
| `server.py` | Python 标准库信令服务器 |
| `tests/test_server.py` | 房间生命周期、鉴权信令和健康检查测试 |
| `scripts/build.sh` | 格式化、检查、测试、编译和产物复制 |

### 通道设计

- `voice`：每对成员一条 PeerConnection，携带独立麦克风轨道。
- `stage`：按拓扑父子关系建立 PeerConnection，携带屏幕视频和来源音频。
- 两个通道独立恢复，语音异常不会导致画面重建。

### 浅层树规划

`lib/topology.mbt` 保证：

- 观众不超过三人时，全部由房主直连。
- 观众超过三人时，选择三个第一层观众，其余观众分配给第一层中转。
- 树深度最多为房主 → 第一层观众 → 叶子观众。
- 每个第一层中转的子节点按加入顺序轮询分配。

成员加入或离开时，房主重新发布拓扑；第一层观众收到画面轨道后，向其子节点建立 outbound stage 连接。

## 快速开始

### 1. 构建

```sh
./scripts/build.sh
```

脚本执行：

```text
moon fmt
moon check
moon test
python3 -m unittest discover -s tests -v
moon build --target js
```

### 2. 启动

```sh
python3 server.py --host 127.0.0.1 --port 8000
```

打开：

```text
http://127.0.0.1:8000/
```

### 3. 演示流程

1. 房主输入昵称，点击 **创建房间**。
2. 四位观众分别输入昵称和房间码，点击 **加入房间**。
3. 浏览器授权麦克风后，成员间自动建立语音 mesh。
4. 房主点击 **共享屏幕和声音**。
5. 选择屏幕来源并勾选共享声音。
6. 前三位观众由房主直连，第四位及之后观众通过第一层观众转发。
7. 观众切换画质档位，房主或中转端会调整发送参数。
8. 点击 **静音麦克风**、**关闭共享声音** 或 **重新连接** 演示控制能力。
9. 点击 **停止共享** 或 **离开** 验证资源释放。

局域网或公网演示需要 HTTPS：

```sh
python3 server.py \
  --host 0.0.0.0 --port 8443 \
  --tls-cert cert.pem \
  --tls-key key.pem
```

### 4. Docker 部署

```sh
docker compose up --build
```

容器会在内部完成 MoonBit 构建、测试和前端产物复制，然后启动信令服务器。默认访问地址仍为 `http://127.0.0.1:8000/`；公网演示建议在容器前配置 HTTPS 反向代理。

## 验证

### 自动化测试

```sh
moon test
python3 -m unittest discover -s tests -v
```

覆盖内容：

- 小房间保持房主直连
- 大房间生成一层中转树
- 房间创建、加入和关闭
- 定向 SDP/ICE 信令投递
- 会话鉴权
- 健康检查

### 浏览器端到端

开发过程中已用 Chromium 完成五页面冒烟：

- 1 位房主 + 4 位观众
- 房主与 4 位观众之间建立 4 条语音连接
- 前三位观众直连房主
- 第四位观众通过第一位观众转发画面
- 第一位观众离开后，剩余观众自动回到房主直连
- 每位观众收到画面与来源音频轨道

## 已知限制

- 默认 STUN 服务器为 `stun:stun.l.google.com:19302`，实际可用性取决于网络环境。
- 对称 NAT 等场景可能无法完成打洞；项目不会回退 TURN。
- 整屏系统声音是否可用由浏览器和操作系统决定。
- 系统混音可能包含远端语音，演示时建议使用耳机。
- 健康监控基于连接状态，尚未实现媒体帧计数和码率采样。
- 房间数据保存在信令服务器内存中，服务重启后房间消失。
- 当前部署面向黑客松演示，尚未包含生产级限流和审计。

## 后续路线

1. **媒体健康采样**：使用 WebRTC stats 检测画面停滞、音频停滞和编码压力。
2. **拓扑择优**：结合 RTT、连接健康和中转 CPU 压力选择第一层节点。
3. **语音恢复增强**：为语音增加媒体计数器与独立恢复策略。
4. **部署完善**：增加生产级限流、审计和证书自动化。
